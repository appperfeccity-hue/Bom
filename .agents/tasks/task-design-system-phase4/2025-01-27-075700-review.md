# Phase 4 Design System: Animations, Accessibility, and Responsive Layout (v2)

CSS-only design system extension adding motion, accessibility landmarks, responsive breakpoints, and loading states to the Perfeccity shell. Two new CSS files (`animations.css`, `responsive.css`) are imported in `main.tsx`. ARIA attributes are applied to layout and dialog components. All five issues from the v1 review have been addressed: `aria-modal` removed from dialogs, breakpoint cascade fixed, live region narrowed to error count, native `<main>` element used, `color: transparent` added to shimmer. Watch for: `aria-live="assertive"` elements mount with error content already present, causing immediate announcement on render (likely); hard-coded transition values bypass existing custom properties (confirmed); panel overlay at 1024px has no dismiss mechanism or backdrop (likely).

**Verdict**: APPROVED

## High-level view

The animation system defines four keyframe animations (panel slide, chip appear, shimmer, and an unused slide-out) plus transition rules for buttons, inputs, tooltips, and cards. All interaction transitions stay at 100–150ms. The `prefers-reduced-motion` block disables all declared animations and transitions. Hard-coded values (`100ms ease`) diverge from the existing `--transition-fast: 120ms ease` custom property, creating two competing timing sources that will drift if the design token is adjusted.

Accessibility coverage includes skip-nav, ARIA landmarks (`<main>`, `role="status"`, `role="banner"`, `aria-label` on nav), dialog roles with `aria-labelledby`, and `aria-live` regions on error elements. The `aria-live="assertive"` divs in BomPanel and FinalizationConfirmDialog are conditionally rendered — they mount only when `error` is truthy, appearing in the DOM already containing text. Screen readers handle this inconsistently; the safer pattern is a persistent empty container whose content changes trigger the announcement.

The responsive CSS separates the two breakpoints: 1025–1280px collapses the left panel and narrows the right; at or below 1024px, both panels become fixed overlays and the icon rail shrinks to 44px. The left panel at 1024px sets `display: block` with fixed positioning but has no toggle, backdrop, or escape-key handler — it will permanently overlay the canvas until a JS toggle mechanism is added.

## Assertive live region mount semantics

In BomPanel, the error div renders conditionally:

```tsx
{error && (
  <div aria-live="assertive" ...>
    Error: {error}
  </div>
)}
```

When `error` transitions from `null` to a string, React mounts this div with text already inside it. The ARIA spec requires assistive technology to announce changes to live regions, but "initial appearance in the DOM with content" is an edge case with inconsistent behavior: NVDA and JAWS typically announce it; VoiceOver sometimes does not. The robust pattern is a persistent container (`aria-live="assertive"`) that remains in the DOM empty, with content injected when an error occurs — guaranteeing the "change" event fires reliably. The same pattern appears in FinalizationConfirmDialog.

## Transition timing divergence

The design system declares `--transition-fast: 120ms ease` in `:root`, and the icon rail uses `var(--transition-fast)` for its hover transition. The new `animations.css` introduces `transition: background-color 100ms ease` for buttons and `100ms ease` for inputs — a different literal value. If the design team later adjusts `--transition-fast`, buttons and inputs won't follow. Using `var(--transition-fast)` in `animations.css` would keep all interaction transitions on a single dial.

## Panel overlay without interaction layer

At 1024px, `.panel-left` gets:

```css
display: block;
position: fixed;
top: 0; left: 0;
height: 100vh; width: 280px;
z-index: 1000;
```

There's no `display: none` default at this breakpoint — the CSS makes `.panel-left` permanently float over the canvas. Without a JS-driven toggle (hamburger menu adding/removing `.panel-left--open`), the panel obscures content at small viewports with no way to dismiss it.
