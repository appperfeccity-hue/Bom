## High-level view

Until it's wired up (likely in the Wall Configuration UI panel not yet in this diff), the stores remain de-facto independent at runtime.

Row height rounding applies a simple `Math.round` without the sum-correction strategy used for columns. For odd divisions (e.g., 2500mm / 3 rows = 833.33mm), each row rounds to 833mm, the sum is 2499mm, and the last row's bottom edge is 1mm short of the wall.

`setWallConfigAndFrames` and `populateZonesFromFrames` in `projectStore` are the only mutation methods that don't check `currentProject?.status === 'FINALIZED'`. Every other write path early-returns when finalized. The wall config path would overwrite zones on a finalized project if the sync subscription fires.

## Row height rounding asymmetry

Column widths go through `applyRoundingWithSumCorrection`, which rounds each width and then redistributes the residual so the sum exactly equals `availableWidth`. Row heights take a simpler path:

```typescript
const rowHeight = Math.round(availableHeight / rows);
```

For `availableHeight = 2500, rows = 3`: each row gets `Math.round(833.33) = 833`. Three rows sum to 2499mm — 1mm short. The frame at `y = 2 * (833 + gap)` doesn't reach the wall bottom. When persisted, the `height_mm` column is consistent (all 833), but the layout doesn't fill the wall. Applying the same sum-correction (give one row the extra mm) would close the gap.

## Finalization guard gap

Every mutation in `projectStore` follows this pattern:

```typescript
if (get().currentProject?.status === 'FINALIZED') return;
```

`setWallConfigAndFrames` and `populateZonesFromFrames` skip this check. If `initWallConfigStoreSync` is eventually wired up and a finalized project's wall config store is somehow modified (e.g., dev tools, stale subscription), zones would be overwritten on a finalized project — violating the immutability expectation.

## Store sync as dead code

`grep -rn "initWallConfigStoreSync" frontend/src/` finds the function only at its definition site (line 314 of `wallConfigStore.ts`). The architecture is correct but not yet activated — the two stores remain disconnected in production until a consumer calls it.
