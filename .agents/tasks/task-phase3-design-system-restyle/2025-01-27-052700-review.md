# Design system token migration for Admin, BOM, and overlay screens

This change replaces all hardcoded Material Design hex colors and inline style values across 43 files with CSS custom properties from the PERFECCITY design system. The scope covers the admin sidebar and six admin CRUD pages, the BOM panel family (7 files), template management (6 files), overlay panels (SkuBrowser, PublishWorkflow, ProjectCreation, Finalization), and the dashboard page. The approach uses CSS custom properties inline (via `var()`) rather than switching to `className`-based composition for most elements, with the exception of admin tables which gain `className="table-minimal"`. All 1094 tests pass, build succeeds, no business logic was modified.

**Watch for:** Inline style objects still dominate over reusable CSS classes — buttons and inputs miss `:hover`/`:focus` states (confirmed); TypeScript type-safety bypass for `fontWeight` via `as unknown as number` casting is inconsistent across files (confirmed); dashboard card shadow uses a hardcoded rgba instead of `var(--shadow-sm)` token (confirmed).

**Verdict**: APPROVED

## High-level view

The token migration is mechanically complete — no Material Design hex values remain in the touched files (only `#ffffff` for white-on-colored-button text, which is intentional). The color mapping is consistent: blue → accent, green → success, red → error, orange → warning.

The implementation chose inline `style={{ }}` with CSS variable references for all buttons and inputs rather than applying the `className="btn-primary"` / `className="input"` classes defined in components.css. This means buttons and inputs miss the `:hover` and `:focus` states defined in the CSS classes, and future token changes require updating every inline occurrence rather than just the class definition. Since the pre-existing code also had no hover/focus states, this isn't a regression — it's a missed opportunity to adopt the interactive states the design system now provides.

The BOM panel section tabs mentioned in the requirements (pill style, 28px height, 14px radius) are not present in the codebase — the BOM panel renders tables directly without a tabbed interface, so this requirement appears to reference a UI element that doesn't yet exist.

The `as unknown as number` TypeScript double-cast appears in 4 places (BomSectionTable, BomPanel) while 39 other occurrences of `fontWeight: 'var(--weight-semibold)'` across admin pages compile without the cast. The inconsistency suggests an unnecessary workaround in those files.

## Inline styles vs CSS classes — missed hover/focus states

The design system provides interactive pseudo-class styles:

```css
.btn-primary:hover {
  background-color: color-mix(in srgb, var(--color-accent) 85%, black);
}
.input:focus {
  border-color: var(--color-accent);
  box-shadow: 0 0 0 2px rgba(154, 123, 79, 0.2);
}
```

None of the 43 modified files use these classes. All buttons replicate `.btn-primary`'s resting properties inline:

```tsx
style={{ backgroundColor: 'var(--color-accent)', color: '#ffffff', border: 'none',
         borderRadius: 'var(--radius-sm)', padding: '6px 12px', fontSize: 'var(--text-base)',
         fontWeight: 'var(--weight-medium)', cursor: 'pointer' }}
```

Users get no hover darkening on buttons and no focus ring on inputs. The VALIDATED BOM badge also applies its border inline rather than using the existing `.status-chip--validated` class from components.css.

## Reconciliation double-call

In BomReconciliationView.tsx, the badge rendering calls `getResultStyle(line.result_type)` twice per row:

```tsx
backgroundColor: getResultStyle(line.result_type).backgroundColor,
color: getResultStyle(line.result_type).color,
```

A single destructure before the style object would be cleaner and avoid the redundant switch evaluation.

## Dashboard card shadow token divergence

The DashboardPage `cardStyle` uses `boxShadow: '0 1px 2px rgba(0,0,0,0.04)'`. The design system defines `--shadow-sm: 0 1px 2px rgba(26, 26, 26, 0.05)`. The previous code referenced `var(--shadow-sm)`. The new literal diverges from the token — minor visual difference but breaks the single-source-of-truth principle the rest of the migration establishes.
