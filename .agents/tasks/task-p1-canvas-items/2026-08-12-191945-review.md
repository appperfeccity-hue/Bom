# P1 Canvas Layers, SKU Render/Remove, and Validation UX

This change adds three new canvas visualization layers (Lighting, Furniture, Trim), a SKU render asset layer with signed-URL image loading and text fallback, a zone removal action, and a full validation UX pipeline (red outlines, error badges, properties panel errors, publish gate indicator). It also fixes five P0 follow-ups: history reset on template switch, nudge debounce, subscriber cleanup, UUID validation on permission keys, and permission-range priority documentation. The architecture remains clean — layers consume store state without embedding business logic, validation is a pure hook, and the new `removeSku` store action uses optimistic update with rollback.

Watch for: signed URL cache never expires within a session (confirmed), `useSkuRenderUrls` fires sequential awaits per SKU instead of batching (confirmed), the `useHistory` module singleton leaks state between test suites if `resetHistory` isn't called (confirmed, mitigated by explicit resets in tests).

**Verdict**: APPROVED

## High-level view

The SKU render pipeline chains three async hops — catalogue entry lookup, asset file-reference fetch, and signed URL generation — serialized per SKU. This works for low zone counts but will become a visible bottleneck at 10+ zones because each iteration awaits individually. The signed URL cache (`signedUrlCache` ref) has no TTL; URLs created with a 1-hour expiry will silently 403 after that window without triggering a re-fetch unless `zoneSku` identity changes.

History management is now a proper singleton with subscriber cleanup, template-reset, and nudge debounce. The debounce uses wall-clock comparison which means a user who nudges, pauses >300ms, and nudges again gets separate history entries rather than one continuous drag — acceptable for keyboard nudging.

Validation runs synchronously in `useMemo` checking overlap (O(n²)), bounds, and minimum dimensions. At typical zone counts (<50) this is negligible. The overlay layer does two passes over invalid zones (circles then text) but contains a dead `errorCount` variable in the first pass.

The `removeSku` action uses optimistic update with rollback, but there's an asymmetry: `useSkuRemove` pushes history *before* calling `removeSku`, so a DB failure rolls back `zoneSku` in the store but leaves a stale history entry. Undo after a failed removal could produce confusing state.

Permission enforcement now short-circuits on non-UUID zone IDs. The `MeasurementPanel` correctly orders permission validation before generic range clamping, addressing the follow-up about priority.

<summary>Issues (4)</summary>

1. **Signed URL cache has no TTL** — `signedUrlCache` in `useSkuRenderUrls` retains URLs indefinitely within a session. After the 1-hour expiry, images will 403 silently until the component remounts or `zoneSku` reference changes. Add a timestamp per entry and discard stale URLs on access.
2. **Sequential signed URL generation** — `useSkuRenderUrls` awaits `createSignedUrl` in a for-loop per zone. Batch with `Promise.all` (or at least parallelize) to avoid waterfall latency with many zones.
3. **Unused `errorCount` variable** — `ValidationOverlayLayer` declares `const errorCount` in the first `.map()` callback but never uses it (the count is computed again in the second `.map()`). Dead code; remove the first declaration.
4. **Image cache grows without bound** — `imageCache` in `SkuPlacementLayer` is keyed by URL string and never evicts entries. Over a long session with multiple templates, this accumulates `HTMLImageElement` references. Consider a bounded LRU or clearing on template switch.

## Signed URL lifecycle and cache gaps

The image loading path in `SkuPlacementLayer` maintains two caches: `imageCache` (URL → HTMLImageElement) and `failedUrls` (Set of URLs that errored). Neither is cleared on template switch — only new URLs trigger fetches. Since `imageCache` is a `useRef`, it resets when the component unmounts (template switch destroys children), so the stale-URL problem only manifests if the component stays mounted for over an hour while signed URLs expire. The `signedUrlCache` in `useSkuRenderUrls` is a module-level ref that persists across remounts with no expiry tracking at all — this is the more concerning cache.

There's no loading indicator; zones with pending fetches render nothing until the image arrives or fails. On slow connections this produces a visible flash from empty to rendered.

## Sequential URL generation waterfall

`useSkuRenderUrls` batches the catalogue entry lookup (`in('sku_id', uncachedSkuIds)`) but signed URL generation iterates sequentially:

```typescript
for (const [zoneId, sku] of zoneSku.entries()) {
  const { data } = await supabase.storage
    .from('catalogue-assets')
    .createSignedUrl(fileRef, 3600);
}
```

Each `createSignedUrl` is a network round-trip. With 10 zones this adds ~10× single-URL latency to initial render. The `fileRefCache` and `signedUrlCache` mitigate repeat calls, but first load of a template with many distinct SKUs will waterfall.

## removeSku history asymmetry

`useSkuRemove` pushes history (zones snapshot) then calls `projectStore.removeSku`. The store action optimistically removes the `zoneSku` entry and issues a DB delete. On failure, it rolls back `zoneSku` and sets `error` — but the history entry remains. If the user then undoes, they restore a zones snapshot that predates the (now-rolled-back) removal. The undo itself doesn't touch `zoneSku`, so the state ends up internally consistent, but the UX is confusing: undo appears to do nothing because the removal was already rolled back. This is a minor edge case given DB failures are rare, but the pattern could be tightened by popping the history entry on rollback.

## Validation overlay dead variable

`ValidationOverlayLayer` declares `const errorCount = validation.errors.length` in the Circle-rendering pass but never references it — the count is only used in the Text-rendering pass. This is a leftover from when both were likely in the same block.
