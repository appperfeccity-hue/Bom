# Multi-select, copy/paste, snapping, L-corner segments, and mobile touch for canvas zones

This change implements seven P2 Canvas items across four feature batches: multi-select with Shift+Click and marquee (P2-6), copy/paste/duplicate with BOM↔Canvas bidirectional highlighting (P2-5, P2-1), L-corner segment assignment with per-zone dimension annotations (P2-2, P2-3), and object/wall edge snapping with mobile responsive touch (P2-4, P2-7). The approach extends `canvasStore` with a `selectedZoneIds[]` array and layered feature hooks, keeping the existing single-zone path as a degenerate case of the multi-select array. Pure utility functions (`snapEngine`, `segmentAssignment`, `segmentConstraint`) are cleanly separated from rendering, and the change adds 87 new tests bringing the suite to 901.

Watch for: horizontal snap guide lines render at wrong Y position due to missing coordinate inversion (confirmed); Toolbar delete bypasses history push unlike the keyboard handler (confirmed); marquee fires on every mouse move even during zone creation (likely).

**Verdict**: NEEDS_CHANGES

## High-level view

The selection model moves from a single `selectedZoneId` to a `selectedZoneIds[]` array, with all downstream code (drag, nudge, delete, resize handles) branching on array length. The migration is complete—every test helper and store consumer now initializes the extended `SelectionState` shape.

Edge snapping uses a two-function pipeline (`getSnapCandidates` → `snapToEdges`) that operates in the zone coordinate system (bottom-left origin). The `SnapGuidesLayer` renders those horizontal positions directly in Konva's top-left coordinate space without inverting Y, so horizontal guides will appear at `y` instead of `wallHeight - y`.

The Toolbar's delete button removes selected zones without pushing history or clearing selection, while the keyboard Delete path does both. This means toolbar deletions are not undoable.

Marquee selection and zone creation both start on the same `mousedown` event; the marquee continues tracking during zone creation drags and fires `setMarqueeRect` every move. The 5px minimum threshold prevents a spurious select, but the redundant state updates during creation are unnecessary work.

Copy/paste uses a `performPaste` helper extracted outside the Zustand store to avoid circular `set()` calls. It iterates paste offsets in 100mm increments (up to 10 attempts) when overlap is detected, falling through silently if all attempts fail—the zone is placed overlapping.

L-corner segment enforcement is applied consistently at create, drag-end, and resize-end. The `projectStore.updateZone` also auto-computes segment on every position change, providing defense-in-depth for any code path that moves a zone.

## Snap guide Y-axis inversion bug

The snap engine's `getSnapCandidates` collects horizontal positions from `zone.y_mm` and `zone.y_mm + zone.height_mm`, which are distances from the wall's bottom edge. When `snapToEdges` returns `snappedHorizontal`, it's in this same bottom-left coordinate space. The `useZoneDrag` hook stores it in `activeSnapLines.horizontal`.

`SnapGuidesLayer` renders:

```tsx
points={[0, y, wallWidth, y]}
```

Konva's Y-axis runs top-down. A snap position of, say, `200` (200mm from bottom) should render at `wallHeight - 200` in Konva coordinates. Without this inversion, horizontal guides appear mirrored vertically. Vertical snap guides are unaffected because X doesn't invert between coordinate systems.

## Toolbar delete bypasses undo history

The keyboard shortcut handler (`useKeyboardShortcuts`, Delete/Backspace path) correctly calls `history.pushState(zones)` before deleting and calls `clearSelection()` after. The Toolbar's `handleDeleteZone`:

```ts
const handleDeleteZone = () => {
  const selectedIds = selection.selectedZoneIds;
  if (selectedIds.length > 0) {
    for (const id of selectedIds) {
      void removeZone(id);
    }
  }
};
```

No history push, no selection clear. Users who click the toolbar button instead of pressing Delete lose undo capability for that action, and the selection retains references to deleted zones.

## Marquee fires during zone creation

In `CanvasContainer.handleStageMouseDown`, both `handleCreateStart` and `handleMarqueeStart` are called unconditionally. During `handleStageMouseMove`, `handleMarqueeMove` is called outside the `if (isCreating)` block, so every creation drag also updates marquee state. The `handleMarqueeEnd` threshold (`width > 5 && height > 5`) prevents a spurious selection at the end, but the per-frame `setMarqueeRect` updates during zone creation are wasted renders. A guard like `if (!isCreating)` around the marquee move/end calls would eliminate this.

## Paste overlap fallthrough

`performPaste` iterates offsets:

```ts
while (hasOverlap(box, allZones) && attempts < 10) { ... }
```

After 10 failed attempts, it proceeds to create the zone at whatever coordinates remain. For dense canvases, this silently creates overlapping zones—contradicting the constraint system that prevents overlap everywhere else. A better behavior would be to skip the zone and optionally notify the user.

## Multi-drag without snapping

`handleDragMove` only invokes `snapToEdges` in the `else` (single-zone) branch. The multi-drag branch computes group constraint but never calls `setActiveSnapLines`, so no visual snap guides appear. This is a UX gap: users selecting two zones and dragging them near a wall edge get no snap feedback. Whether this is intentional (to avoid complexity of group-level snapping) or an oversight is worth clarifying.

## Test coverage

The new 87 tests cover store actions (multi-select, toggle, marquee rect), keyboard shortcuts (batch delete, batch nudge, copy/paste/duplicate), snap engine pure functions, segment assignment logic, BOM-canvas link state, and touch viewport math. The `ZoneDimensionsLayer` rendering test verifies labels appear for each zone.

Not tested: the coordinate inversion behavior of `SnapGuidesLayer` (the bug above would be caught if a rendering test verified Y positions); the Toolbar delete interaction (no integration test for the button's click handler with history); the `useMarqueeSelect` hook in isolation (tested only through keyboard-shortcut integration); touch event handlers on `CanvasContainer` (touch tests verify math but not the actual `onTouchMove` wiring).
