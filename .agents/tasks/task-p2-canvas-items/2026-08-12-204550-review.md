# Multi-select, copy/paste, snapping, segments, dimensions, and touch support (v2)

This is the second review pass. All five issues from v1 have been fixed: snap guide Y-inversion, toolbar delete with history/clear, marquee guard during zone creation, paste skipping zones on non-source overlap after 10 attempts, and multi-drag snapping with visual feedback. The implementation is now consistent across code paths and the suite holds at 901 tests passing with only 2 pre-existing TS errors.

Watch for: pinch-zoom doesn't anchor to the pinch center the way scroll-wheel zoom anchors to the cursor (confirmed); BOM line highlights persist after zone deselection since `clearSelection` doesn't reset `highlightedBomLineIds` (confirmed); multi-drag snap can theoretically push the group's far edge outside wall bounds since snapping is applied after constraint (possible).

**Verdict**: APPROVED

## High-level view

The pinch-zoom implementation applies the scale ratio directly to the current zoom without compensating the pan offset to keep the pinch center stable. This is the same bug class as a scroll-zoom that zooms toward the viewport origin rather than the cursor—functional but disorienting on touch devices.

BOM-to-canvas highlighting is half-lifecycle: `handleRowMouseLeave` clears zone highlights, and zone click sets BOM line highlights, but nothing clears `highlightedBomLineIds` when the zone is deselected or when clicking empty canvas. Gold BOM rows remain highlighted until the user clicks a different zone or explicitly hovers/leaves a BOM row.

The snap-after-constrain ordering in both single-drag and multi-drag means a snap delta could theoretically shift the group's far boundary outside the wall. In practice the 10mm threshold and typical zone geometry make this unlikely, but the invariant isn't enforced.

<summary>Issues (3)</summary>

1. **Pinch-zoom not center-anchored** — `handleTouchMove` multiplies zoom by the pinch scale but doesn't adjust pan to keep the pinch midpoint stable. Apply the same pan correction as `handleWheel` uses for cursor-centered zoom.
2. **BOM line highlights stale after deselection** — `clearSelection()` resets selection state but not `highlightedBomLineIds`. Add `highlightedBomLineIds: []` to the `clearSelection` setter, or clear it in `selectZone(null)`.
3. **Snap-after-constrain ordering** — Both single-drag and multi-drag apply wall constraint *then* edge snap. A snap delta could theoretically push the far edge outside wall bounds. Consider re-applying `constrainToWall` after snapping, or clamping the snap result.

## Pinch-zoom center drift

The scroll-wheel zoom in `handleWheel` computes a pan adjustment to keep the mouse position stable:

```ts
const dx = mouseX - (mouseX - viewport.panX) * (newZoom / oldZoom) - viewport.panX;
const dy = mouseY - (mouseY - viewport.panY) * (newZoom / oldZoom) - viewport.panY;
```

The touch handler applies zoom but only pans by the center-point translation between frames:

```ts
const scale = newDistance / lastTouchDistance.current;
setZoom(currentViewport.zoom * scale);
// Then separately:
const panDx = newCenter.x - lastTouchCenter.current.x;
const panDy = newCenter.y - lastTouchCenter.current.y;
pan(panDx, panDy);
```

The pan delta only accounts for finger translation, not for the zoom-induced expansion around the center. On a real device, the canvas will drift away from the pinch point as zoom increases. The fix is the same pan compensation formula used in the wheel handler, substituting pinch center for mouse position and `newZoom / oldZoom` for the scale ratio.

## BOM highlight lifecycle gap

When a zone is clicked, `ZonesLayer.handleZoneClick` calls `setHighlightedBomLineIds(matchingLineIds)`. But `clearSelection` only resets the selection object:

```ts
clearSelection: () =>
  set({
    selection: { selectedZoneId: null, selectedZoneIds: [], resizeHandle: null, marqueeRect: null },
  }),
```

Neither `highlightedBomLineIds` nor `highlightedZoneIds` is touched. The BOM panel's `handleRowMouseLeave` clears zone highlights (canvas-to-BOM direction works), but deselecting a zone leaves its BOM rows gold-highlighted indefinitely. Adding `highlightedBomLineIds: []` to `clearSelection` (and to `selectZone` when called with a different zone) would close the lifecycle.

## Dimension label units

`ZoneDimensionsLayer` renders `${zone.width_mm}` as the label text—a bare number without a "mm" suffix. The requirement specifies "mm labels on zone edges." Non-blocking, but adding the unit suffix would match the spec and avoid ambiguity when the wall measurement layer is hidden.
