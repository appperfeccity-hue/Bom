# Site Adaptation Engine — v2 review after fixes

The v1 review raised four issues; all four have been addressed. Zone-sum coherence is now validated (1mm tolerance), height field pairing is enforced (both-or-neither), the truthy check was replaced with explicit `!== undefined && !== null`, and zone_id uniqueness is validated upfront. Six new tests cover these fix paths, bringing the total to 41. All pass, typecheck is clean.

Watch for: `template_wall_height: 0` with `DERIVED_FROM_WALL` produces NaN heights that slip through constraint enforcement and appear as `null` in the output (confirmed).

**Verdict**: APPROVED

## High-level view

The zero-height division edge case is the only new functional gap. When both wall heights are zero, `0/0 = NaN` propagates through `Math.round` into the output as `NaN` (serialized as `null`). The constraint comparisons (`NaN < min` and `NaN > max`) are both false in IEEE 754, so the check passes silently. When `template_wall_height` is 0 but `actual_wall_height` is nonzero, `Infinity` is produced and caught by the max-height constraint — the error message references "Infinitymm" which is confusing but at least fails closed. A single validation line rejecting non-positive wall heights when provided would close both paths.

## NaN propagation from zero wall heights

The validation function confirms both wall-height fields are either present or absent, but never checks their values. The height-activation branch at line 357 computes:

```typescript
const heightRatio = input.actual_wall_height / input.template_wall_height;
```

When `template_wall_height` is 0:
- `actual_wall_height > 0` → `heightRatio = Infinity` → `Math.round(height_mm * Infinity) = Infinity` → caught by `height > maxHeight` constraint → throws with "Infinitymm" in the message
- `actual_wall_height === 0` → `heightRatio = NaN` → `Math.round(height_mm * NaN) = NaN` → `NaN < minHeight` is false, `NaN > maxHeight` is false → passes constraint check → output contains `NaN` which JSON serializes to `null`

The second path produces output that violates the TypeScript interface (`adapted_height_mm?: number`) without any error. The fix is a positivity guard in `validateInput`:

```typescript
if (hasTemplateHeight && input.template_wall_height! <= 0) {
  throw new EngineError('template_wall_height must be positive when provided');
}
if (hasActualHeight && input.actual_wall_height! <= 0) {
  throw new EngineError('actual_wall_height must be positive when provided');
}
```

The existing test for zero heights only exercises `FIXED` mode which never touches the ratio, so this path has no coverage.
