# Designer configuration panels for Mounting Rules, Trims, and Product Relationships (v2)

Three CRUD panels (MountingRules, Trims, ProductRelationships) follow the established HiddenComponents pattern: each fetches from and writes to a Supabase table, guards rendering behind `CanvasMode.DESIGNER`, and pairs a list panel with a dialog form. All four issues from the v1 review have been addressed: SKU search is debounced at 300ms with clearTimeout on re-fire, delete errors trigger optimistic-removal rollback plus error display, the `.or()` filter validates IDs with `isSafeFilterId` before interpolation, and negative `fixed_quantity` values are clamped with `Math.max(0, ...)`. No blocking concerns remain.

**Verdict**: APPROVED

## High-level view

The MountingRules panel derives gap and structure metadata from a pure-function lookup (`getMountingInfo`) keyed by mounting type. The derivation is deterministic and extracted to a named export, making it independently testable and reusable by the dialog.

The Trims panel gates its fixed-quantity field behind the `TRIM_FIXED` rule and enforces that PHYSICAL trims require a SKU ID. The negative-quantity concern from v1 is closed: the dialog applies `Math.max(0, Number(fixedQuantity))` before insert.

ProductRelationships is the most complex panel. It aggregates SKU IDs from three tables, constructs a PostgREST `.or()` filter from validated IDs (characters that would corrupt filter syntax are rejected by `isSafeFilterId`), and provides debounced SKU search for the relationship dialog. Delete operations now capture errors, roll back the optimistic removal, and surface the failure message in a `remove-error` element. The self-relationship guard (`source === target`) prevents degenerate records.

## Non-blocking observations

The `ilike` search in `AddRelationshipDialog` interpolates raw user input into the pattern (`%${sourceQuery}%`). PostgreSQL LIKE wildcards (`%`, `_`) in the typed value would match more broadly than the user expects — typing `LED_%` matches any single character after `LED_` rather than a literal underscore. The capped result set (`.range(0, 19)`) limits the blast radius.

The three panels do not surface fetch errors to the user — `fetchRules`, `fetchTrims`, and `fetchData` all silently ignore `{ error }` from the initial data load. This matches the existing `HiddenComponentsPanel` convention and is not a regression introduced by this diff.
