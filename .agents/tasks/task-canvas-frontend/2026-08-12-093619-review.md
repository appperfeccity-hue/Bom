# Konva dual-mode canvas with Zustand state and Supabase persistence

This change adds a complete React+TypeScript+Vite frontend in `/frontend` implementing a 2D canvas editor for wall zone layouts. The application models two personas (Designer and Consultant) operating on the same spatial data: the Designer creates and edits zones within a wall boundary, the Consultant enters site measurements. State lives in three Zustand stores (auth, project, canvas) and persists through a Supabase client targeting the `perfecity` schema. A pure-function constraint engine enforces min/max zone sizes, wall boundary containment, overlap detection, and a 12-zone cap. 67 tests cover the constraint functions, coordinate transforms, canvas store, and a thin integration layer over the Konva Stage mock.

Watch for: the autosave debouncer (`createDebouncedSave`) is defined but never wired into any store action (confirmed); ZonePropertiesPanel bypasses all constraint validation, allowing the user to type values outside the legal range and persist them directly (confirmed); overlap detection exists in the constraint module but is never called from any creation or drag path (confirmed); resize handles render but have no pointer-event handlers, so resize via handles does not actually work (confirmed).

**Verdict**: NEEDS_CHANGES

---

## High-level view

The coordinate system is internally consistent: every layer applies `wallHeight - y - height` to bridge bottom-left canvas origin to Konva's top-left origin, and the coordinate transform utilities are well-tested. This means the issues below are logic/wiring gaps, not geometry bugs.

The constraint engine (`zoneConstraints.ts`) is well-tested but its reach stops at `useZoneCreate`. Neither the drag hook, the resize hook, nor the properties panel invoke `hasOverlap`, meaning two zones can freely overlap via any mutation path. The max-zone check similarly only guards creation.

The autosave infrastructure is orphaned. `createDebouncedSave` exists with correct debounce-then-persist semantics, but the project store fires raw Supabase calls inline. The `saveStatus` field in the canvas store is never transitioned — the toolbar save indicator will always read "Saved" regardless of actual persistence state.

The resize interaction is visually complete (handles render) but functionally disconnected — nothing binds pointer events on the handle Rects to the `useZoneResize` hook callbacks.

Supabase access is unguarded: no session-expiry handling, no auth listener activation, and `fromTable` has no error boundary. Writes fail silently into a state field that nothing surfaces to the user.

<summary>Issues (7)</summary>

1. **Autosave not wired** — `createDebouncedSave` is never called; all store mutations hit Supabase directly without debounce, and `saveStatus` never transitions. Wire the debouncer into `updateZone`/`addZone`/`removeZone` or delete the dead code.
2. **Overlap detection unused** — `hasOverlap` and `doBoxesOverlap` are tested but never invoked from zone creation, drag, or resize paths. Zones can overlap freely. Call `hasOverlap` in `useZoneCreate.handleCreateEnd`, `useZoneDrag.handleDragEnd`, and `useZoneResize.handleResizeEnd`.
3. **Resize handles inert** — `SelectionLayer` renders handle Rects without `onMouseDown`/`onDragStart` handlers; `useZoneResize` is unused. Bind pointer events on each handle Rect to `handleResizeStart` so resize is functional.
4. **ZonePropertiesPanel bypasses constraints** — Direct numeric inputs call `updateZone` with no clamping, no wall-boundary check, and no overlap check. A user can type `width_mm: 50000` and it persists. Route changes through `clampDimensions` + `constrainToWall` before calling `updateZone`.
5. **Session expiry unhandled** — `fromTable` has no pre-flight session check. If the Supabase token expires, writes fail silently (caught, state `error` set, but no user-visible notification). `authStore.subscribeToAuthChanges()` is never called from `App.tsx` or `main.tsx`, so auth state goes stale. At minimum, activate the listener and surface errors.
6. **fitToViewport re-runs on every resize** — `useEffect` depends on `[currentTemplate, stageSize, fitToViewport]`. Every window resize resets zoom/pan, discarding the user's current viewport. Guard with a `hasInitialized` ref.
7. **`void index` no-op in ZonesLayer** — `void index;` suppresses the unused-variable warning but the variable is used in the label map below. Remove the misleading suppression.

<summary>Details</summary>

## Autosave plumbing gap

`createDebouncedSave` in `lib/autosave.ts` transitions through `unsaved → saving → saved | error`, accepts a version parameter for optimistic locking, and exposes `cancel`/`flush`. None of this is referenced anywhere. The project store's `updateZone` directly awaits `fromTable('template_zone').update(...)`. The canvas store's `setSaveStatus` is never called.

The toolbar's save indicator always displays "Saved" because `saveStatus` is initialized to `'saved'` and nothing mutates it. Instantiate `createDebouncedSave` within the project store and route all write actions through it.

## Overlap detection is tested but never enforced

`zoneConstraints.ts` exports `hasOverlap(box, existingZones, excludeId?)` with tests covering edge-touching, self-exclusion, and general overlap. However:

- `useZoneCreate.handleCreateEnd` calls `constrainToWall` but never `hasOverlap`.
- `useZoneDrag.handleDragEnd` updates position without checking overlap.
- `useZoneResize.handleResizeEnd` writes new bounds without overlap validation.
- `ZonePropertiesPanel` writes arbitrary coordinates without any spatial check.

Two zones can freely overlap in every mutation path.

## Resize handles are visual-only

`SelectionLayer.tsx` renders eight `<Rect>` elements at handle positions with no `onMouseDown`, `onDragStart`, or `onPointerDown` handlers. `useZoneResize` is imported nowhere in the rendering tree.

Connecting them requires attaching `onMouseDown={() => handleResizeStart(zone, handle)}` on each handle Rect and forwarding subsequent mouse events through `handleResizeMove`/`handleResizeEnd` at the Stage level (Konva drag on small Rects without explicit drag binding is unreliable).

## ZonePropertiesPanel: unconstrained writes

The panel passes raw parsed ints to `updateZone` with no constraint check:

```tsx
onChange={(e) => handleFieldChange('width_mm', parseInt(e.target.value, 10) || 0)}
```

A user typing `width_mm: 0` or `width_mm: 99999` persists immediately. This bypasses the constraint system that canvas interactions enforce.

## fitToViewport triggers on every container resize

```tsx
useEffect(() => {
  if (currentTemplate && stageSize.width > 0) {
    fitToViewport(...);
  }
}, [currentTemplate, stageSize, fitToViewport]);
```

`stageSize` updates on every window resize event. Every browser resize discards manual zoom/pan. Guard with a `hasInitialized` ref so it runs only on mount and template change.

## Supabase client and session lifecycle

If either env var is missing, the client is created with empty strings — producing a non-functional client whose queries fail with opaque network errors rather than an explicit guard.

`authStore.subscribeToAuthChanges()` is never called from the component tree. If a token refreshes or expires while the tab is open, `user`/`role` state will be stale and subsequent RLS-protected writes will fail without explanation.

## Test coverage gaps

Not tested: integration between interaction hooks and project store (drag → updateZone → Supabase); autosave debounce behavior; auth flow; measurement panel validation; L_CORNER wall geometry rendering; viewport zoom-to-cursor centering math; error recovery on Supabase failures.
