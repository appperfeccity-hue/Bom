## High-level view

The autosave pipeline is now sound: `pendingZoneUpdates` is a Map that accumulates one closure per zone ID, and `getAutosaver`'s `saveFn` drains the entire map with `Promise.all` when the debounce fires. Multiple zone edits within the 2-second window are all persisted.

Zone creation overlap detection now uses the current `zones` array reference in its dependency list, matching the pattern already established in `useZoneDrag` and `useZoneResize`. The closure always captures fresh positions regardless of whether the zone count changed.

## Partial rollback under concurrent failure

Each `updateZone` closure captures `prevZones` from its own call site. When the debounce fires and `Promise.all` executes all pending closures, if zone A's persist fails after zone B's succeeds, zone A's rollback sets local state to its captured `prevZones` — which already contains zone B's optimistic change. Zone B stays committed on the server, so there's no divergence for B. But A's local state reverts while its server state was never written, which is the correct behavior for an optimistic update. The edge case is that the `error` state in `canvasStore.saveStatus` fires once for the overall batch even though only one zone failed — the user sees "Error saving" without knowing which zone. This is a UX limitation, not a data-integrity issue.
