# Design system shell and token layer for Perfeccity

This change introduces a visual design system layer for the Perfeccity Canvas application: CSS custom properties defining a warm architectural color palette, Google Fonts integration (Inter + IBM Plex Mono), a CSS Grid–based application shell (56px icon rail, 56px top bar, flexible content area, 24px status bar), and four new layout components (`AppShell`, `IconRail`, `TopBar`, `StatusBar`). The `DashboardPage` is migrated to use CSS variable tokens. All 1094 existing tests continue to pass; no business logic or stores were modified.

Watch for: The IconRail navigates to routes that don't render inside the AppShell, causing full-page transitions that lose the rail context (confirmed). `TopBar` uses `as unknown as number` casts to pass CSS variable strings to the `fontWeight` inline style property — these work at runtime but abuse the type system (confirmed). Collapsible panels are defined in CSS but never wired to any toggle mechanism (confirmed, likely intentional as scaffolding).

**Verdict**: APPROVED

## High-level view

The token layer (`design-system.css`, `typography.css`) defines the complete palette, spacing scale, and type system via `:root` custom properties, with fonts loaded through a single Google Fonts `@import` in CSS rather than a `<link>` tag. The CSS-level import creates a render-blocking chain (stylesheet parse → font CSS fetch → font file fetch) that could be flattened with a `<link>` in `index.html`, though the `display=swap` parameter mitigates the visible impact.

The layout shell uses a single CSS Grid on `.app-shell` to define the spatial contract: icon rail spans the full height on the left, top bar and status bar bound the content area on top and bottom, and everything else flows into `.main-area`. The grid is wired into only the `/canvas` route through `App.tsx`; the `DashboardPage`, admin routes, and auth routes remain outside this shell, which means the IconRail's navigation links cause navigations that leave the shell entirely.

The IconRail implements tooltip-on-hover with a 300ms delay timer, active-state styling via `useLocation`, and seven navigation items. Two items share the same path (`/canvas`) and the `Settings` item's prefix-matching rule (`/admin`) will match multiple unrelated admin sub-routes, creating ambiguous active states.

The TopBar and StatusBar are presentational components that read from `canvasStore` and display static placeholder data, respectively. The TopBar works around TypeScript's inline-style typing by casting CSS variable strings through `as unknown as number`.

## IconRail routing scope mismatch

The `AppShell` is inserted at exactly one point in the route tree: it wraps the `App` component rendered at `/canvas`. The `DashboardPage` at `/` and all `/admin/*` routes render outside any shell — they use their own `AdminLayout` or no layout at all.

The IconRail includes navigation items pointing to `/`, `/admin/skus`, `/admin/catalogue`, `/admin/design-families`, and `/admin`. When a user clicks "Dashboard" from the canvas, `navigate('/')` fires, React Router unmounts the entire `/canvas` tree (including `AppShell` and the rail), and renders `DashboardPage` without any shell. The user lands on a page with no icon rail, which makes the rail feel like a canvas-specific sidebar rather than a global navigation frame.

The fix is either to hoist `AppShell` above the route switch (wrapping all authenticated routes) or to scope the rail's items to canvas-relevant paths only.

## Active-state ambiguity in navigation items

The `isActive` logic uses prefix matching:

```tsx
if (item.path === '/') return location.pathname === '/';
return location.pathname.startsWith(item.path);
```

Two items share the path `/canvas` ("Templates" and "Projects"), so both highlight when the user is on the canvas. "Settings" maps to `/admin`, which is a prefix of `/admin/skus`, `/admin/catalogue`, `/admin/design-families`, and `/admin/families`. When on any admin route, both the specific admin item (e.g., "SKU Master" at `/admin/skus`) and "Settings" (at `/admin`) will show the active state simultaneously.

The conventional solution is to check items in most-specific-first order and stop at the first match, or to assign unique paths to each item.

## TopBar type casting workaround

The `TopBar` passes CSS variable strings where React expects `number` for `fontWeight`:

```tsx
fontWeight: 'var(--weight-semibold)' as unknown as number,
```

This works at runtime because the browser sees a string in the style attribute, but it lies to TypeScript. A cleaner approach is moving these declarations into a CSS class consumed via `className`, which is consistent with how all other layout components use class-based styling. The double-cast pattern will silently break if React ever validates style values at the object level.

## Tooltip timer lifecycle

`IconRail` stores the hover timeout in a ref but has no `useEffect` cleanup. If the component unmounts while a user is hovering (e.g., route transition triggered by keyboard shortcut), the pending `setTimeout` callback fires and calls `setTooltipVisible(true)` on unmounted component state. In React 18 this produces a no-op rather than a crash, but it's a latent issue that a simple cleanup effect would prevent:

```tsx
useEffect(() => () => {
  if (timerRef.current) clearTimeout(timerRef.current);
}, []);
```
