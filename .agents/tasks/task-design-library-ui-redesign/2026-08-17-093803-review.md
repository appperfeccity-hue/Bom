# Design Library UI redesign — v2 review

The four issues from the v1 review have been addressed: geometry/availability filters are now reachable via a "More Filters" expandable panel, the ephemeral favorite state is documented with a code comment explaining the intentional cosmetic-only design, 36 unit tests cover the three new components, and the `activeCategory` local state has a TECH DEBT comment explaining why it lives outside the store. The composition, store integration, and existing test suite (1242 tests) pass cleanly.

Watch for:
- **Geometry filter value passed without type assertion** (confirmed) — `setWallGeometryFilter(e.target.value)` passes a `string` where `WallGeometryType | null` is expected; `tsc --strict` flags TS2345 on this line.
- **More Filters panel has no integration test** (confirmed) — the new geometry/availability setter UI is not exercised by any test.

**Verdict**: NEEDS_CHANGES

## High-level view

The More Filters panel adds an expandable `<div>` with two native `<select>` elements for geometry and availability. The pattern is sound — it maintains the store-driven filter architecture without visual clutter — but the geometry setter omits the `as WallGeometryType` cast, introducing a strict-mode type error that the Vite build silently ignores.

The test additions are well-structured: each new component gets a dedicated test file with rendering, click interaction, keyboard activation, and ARIA attribute assertions. The gap is that the "More Filters" panel itself — the fix for the biggest v1 concern — has no corresponding test. A single render-and-interact test exercising the full `DesignLibrary` component with the panel open would close that loop.

## Type narrowing gap in geometry filter setter

The More Filters panel passes `e.target.value` directly to `setWallGeometryFilter`:

```tsx
onChange={(e) =>
  setWallGeometryFilter(e.target.value === '' ? null : e.target.value)
}
```

The store's signature is:

```ts
setWallGeometryFilter: (type: WallGeometryType | null) => void;
// WallGeometryType = 'STRAIGHT' | 'L_CORNER'
```

Running `tsc --noEmit --strict` produces:

```
TS2345: Argument of type 'string | null' is not assignable to parameter of type 'WallGeometryType | null'.
```

The Vite build uses esbuild for transpilation and skips full type-checking, so this doesn't block `npm run build`. But it will break any CI step that runs `tsc --strict` (or if the project enables `strict` in `tsconfig.json`). The fix is a one-line cast: `e.target.value as WallGeometryType` — the `<option>` values are hardcoded to `'STRAIGHT'` and `'L_CORNER'`, so the cast is sound.

## More Filters panel lacks test coverage

The v1 review's top concern was that geometry and availability filters were unreachable. The fix adds a "More Filters" button that reveals dropdowns. However, neither the new component-level test files nor the existing `ProjectCreationWizard.test.tsx` exercise this panel. The interaction path — click toggle, expand panel, change geometry select, verify chip appears in `FilterChipBar` — is entirely uncovered. Given that this was the highest-priority fix, a regression test confirming the select values reach the store would be warranted.
