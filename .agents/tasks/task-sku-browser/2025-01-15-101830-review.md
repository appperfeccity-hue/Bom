# SKU Browser panel with Zustand store, filter/grid/detail/assign workflow

This change adds a slide-over SKU browser for designers: type-aligned interfaces for `sku_master` and catalogue tables, a Zustand store with multi-field filtering and three-table join logic, and a four-component UI (SkuBrowser, SkuFilterBar, SkuGrid, SkuDetailPanel) wired from the ZonePropertiesPanel. All five issues from v1 (pagination, debounce, ilike for material/colour, search scope, duplicated `isSelectable`) are resolved. The three v2 issues — pagination count heuristic, PostgREST escaping, and debounce penalizing dropdowns — are also addressed with correct implementations.

Watch for: the `escapePostgrestValue` utility escapes PostgREST meta-characters (`.`, `,`, `(`, `)`) but does not escape SQL `ILIKE` wildcards (`%` and `_`), so a user typing `%` in the search field gets unintended wildcard expansion (confirmed). The debounced text-input effect fires on mount alongside the discrete-filter effect, producing a redundant `fetchSkus()` call 300ms after the initial load (confirmed, low severity).

**Verdict**: APPROVED

## High-level view

The v2 fixes land correctly. The fetch-one-extra pagination pattern avoids misleading page counts when `catalogueStatus` is filtered client-side. The debounce split works as designed: dropdown changes fire immediately, text inputs wait 300ms. One residual gap exists: SQL ILIKE wildcards (`%`, `_`) pass through unescaped, meaning a user can inject arbitrary SQL patterns through the search/material/colour inputs — the practical risk is low (it widens results rather than leaking data) but it's a correctness gap worth noting. The same gap affects the `material` and `colour` `.ilike()` calls which don't go through `escapePostgrestValue` at all.

## ILIKE wildcard passthrough

The `escapePostgrestValue` function targets PostgREST's structural separator characters:

```typescript
function escapePostgrestValue(value: string): string {
  return value.replace(/[.,()\\]/g, (ch) => `\\${ch}`);
}
```

This prevents `.` from being parsed as a field/operator delimiter and `,` from splitting the `.or()` expression. However, the escaped value is interpolated into an `ilike` pattern (`%${escaped}%`), and `%` and `_` are SQL wildcard characters in `ILIKE`. A user entering `100%` as a material filter would match all materials; `_ak` would match "Oak", "Eak", etc. The fix — add `%` and `_` to the escape set:

```typescript
return value.replace(/[.,()\\%_]/g, (ch) => `\\${ch}`);
```

Additionally, the `material` and `colour` filters don't use `escapePostgrestValue` at all:

```typescript
query = query.ilike('material', `%${filters.material}%`);
query = query.ilike('colour', `%${filters.colour}%`);
```

These should pass through the escape function for consistency.

## Double-fetch on initial mount

`SkuFilterBar` runs two effects on mount:

1. The discrete-filter effect sees `isInitialMount.current === true`, sets it to `false`, and calls `fetchSkus()`.
2. The debounced-text effect runs because `filters.searchQuery` (empty string) is in its dependency array — it schedules a second `fetchSkus()` at t+300ms.

Two identical queries fire within 300ms of the browser opening. A `useRef` guard that skips the debounced effect's first invocation would eliminate the redundant call.
