# Warm palette rollout and AppShell routing fix

This change replaces all Material Design blue colors across the canvas layers, toolbar, and config panels with a warm accent palette (#9A7B4F amber/gold, #6E6E6E secondary, #B0413E error), and fixes Phase 1 architectural issues: AppShell now wraps all authenticated routes via a new `AuthenticatedLayout` route component, the IconRail gets unique paths and proper active-state logic, tooltip timers clean up on unmount, and TopBar ditches `as unknown as` type casts in favor of CSS classes. A new `components.css` provides reusable utility classes (buttons, inputs, panels, chips, tables) referenced against the design system tokens.

Watch for: The "Projects" nav item now links to `/projects`, which has no matching route — authenticated users clicking it will hit the catch-all and be redirected to `/login` (confirmed). The TopBar only flags save-status errors visually; `saving` and `unsaved` states are indistinguishable from normal in color (confirmed). All color changes are Konva-inline literals because Konva can't resolve CSS variables — this creates a parallel maintenance path for the palette (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The routing tree was restructured: `ProtectedRoute > AuthenticatedLayout > [pages]` replaces the old per-page `AppShell` wrapping, ensuring the shell renders on Dashboard, Canvas, and Admin equally. However, the IconRail "Projects" item now points to `/projects` which has no matching route — a broken navigation link for authenticated users.

Canvas layers (Grid, WallOutline, Zones, Selection) swap every hardcoded Material color for the new warm palette. Because Konva's `stroke`/`fill` props require literal strings, these values are duplicated from the CSS variable definitions. Any future palette adjustment requires updating both `design-system.css` and every Konva layer file.

The Toolbar shrinks to 40px, replaces blue with accent, and introduces color-coded save-status indicators per state. The TopBar's CSS-class approach only distinguishes error vs normal, creating a visual disagreement between the two components when both are visible on the canvas page.

`components.css` defines reusable classes (`.btn-primary`, `.input`, `.panel`, `.status-chip--*`, `.table-minimal`) using the design-system tokens. None are consumed by any modified component yet — they're dead code until future adoption.

## Dead route for "Projects" nav item

The IconRail previously had both "Templates" and "Projects" pointing to `/canvas`. The fix gives "Projects" a unique path `/projects`. However, no `<Route path="/projects" ...>` exists in the route tree. The catch-all `<Route path="*" element={<Navigate to="/login" replace />} />` sits outside the protected routes block, so clicking "Projects" while authenticated triggers the catch-all, navigating to `/login`, which (since the user is authenticated) likely redirects back to `/` — a confusing double-redirect loop.

The `isActive` logic uses exact match (`pathname === '/projects'`), so the item will never appear active either. The simplest fix is adding a placeholder route inside the `AuthenticatedLayout` block:

```tsx
<Route path="/projects" element={<DashboardPage />} /> {/* placeholder */}
```

## Konva palette duplication

All canvas-layer color values are hardcoded strings with comments like `/* --color-accent */`. Files affected: `GridLayer.tsx`, `WallOutlineLayer.tsx`, `ZonesLayer.tsx`, `SelectionLayer.tsx`, `CanvasContainer.tsx`. The test file `ZonesLayer.validation.test.tsx` also hardcodes the new error color in assertions, meaning a palette change requires edits in 6+ files.

A single `canvasColors.ts` constants module (e.g. `export const ACCENT = '#9A7B4F'`) would allow both layers and tests to reference the same source of truth, reducing the update surface to one file.

## TopBar vs Toolbar save-status divergence

The Toolbar uses a `saveStatusDisplay` map with four distinct colors (amber for saving, green for saved, red for unsaved/error). The TopBar's CSS-class approach only has two visual states: `.top-bar__save-status` (gray) and `.top-bar__save-status--error` (red). On the canvas page, both components are visible simultaneously — "Saving..." appears gray in the TopBar and amber in the Toolbar.

## Zone stroke-width reduction for error states

ZonesLayer now uses `1.5px` stroke for both selected and error states (previously 2px for both). The error-state visual priority wins on color, but stroke width is now identical to a non-error selected zone. The reduced contrast between error and default (1.5px vs 1px, down from 2px vs 1px) may make validation errors less noticeable on small zones — worth verifying visually. (likely)

## `components.css` browser baseline

The `color-mix(in srgb, ...)` function used in `.btn-primary:hover` requires Safari 16.4+ / Chrome 111+. If this is an internal tool with a known browser baseline, no issue. If users might hit older browsers, the hover state will fail silently (no darkening). (possible)
