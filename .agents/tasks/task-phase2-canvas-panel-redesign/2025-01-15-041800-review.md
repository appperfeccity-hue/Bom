# Warm palette rollout and AppShell routing fix (v2)

This change replaces Material Design blue across the canvas layers, toolbar, and config panels with a warm accent palette (#9A7B4F, #6E6E6E, #B0413E), restructures routing so all authenticated pages render inside the AppShell, and introduces a `components.css` utility layer built on the design system tokens. The v1 review flagged four concerns: the dead `/projects` route has been fixed (route now exists in `main.tsx`), and the TopBar save-status color divergence has been resolved (per-state CSS classes now match the Toolbar's color scheme). The remaining two v1 concerns (Konva palette duplication, unused `components.css`) were accepted as inherent trade-offs.

Watch for: `components.css` uses `color-mix(in srgb, ...)` which requires Chrome 111+/Safari 16.4+ — when these classes are adopted, verify the browser baseline (possible).

**Verdict**: APPROVED

## High-level view

The routing fix is complete: `AuthenticatedLayout` wraps all protected routes, `/projects` resolves to `DashboardPage`, and the IconRail tooltip timer cleans up on unmount via `useEffect` return. The TopBar's per-state save-status classes (`--saving`, `--saved`, `--unsaved`, `--error`) now mirror the Toolbar's warm color semantics, closing the v1 divergence.

Canvas layers use a consistent warm palette with commented variable references. WallConfigPanel and MeasurementPanel extract style constants at module scope (`SECTION_HEADER_STYLE`, `LABEL_STYLE`, `INPUT_STYLE`) as a migration bridge toward the utility classes in `components.css`.

## `color-mix` browser baseline

The `.btn-primary:hover` rule in `components.css` uses:

```css
background-color: color-mix(in srgb, var(--color-accent) 85%, black);
```

This CSS function is supported in Chrome 111+, Safari 16.4+, Firefox 113+. Since `components.css` classes aren't consumed by any component in this diff, there's zero runtime effect today. When adoption begins, if the app targets older browsers, the hover will simply not darken — no visual breakage, just missing hover feedback. A fallback (explicit hex color) or a `@supports` guard would eliminate the risk.
